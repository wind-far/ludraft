# 多类型游戏展示与演示顺序

三消只是其中一种。`scripts/seed_examples.py` 为四种模式创建人工编写的模板配置，仅在真实容器验证通过后导入。它们不证明模型生成质量；已有示例及版本保留，不自动替换。

| 案例 | 模式与配置 | 试玩重点 |
| --- | --- | --- |
| 宝石花园 | match3：六色、20 步、1200 分 | 相邻交换、无效回退、连锁、目标和步数 |
| 星光收集站 | collector：3 条生命、60 秒 | 左右移动、接物得分、碰炸弹扣命 |
| 流星闪避 | dodger：3 条生命、60 秒 | 躲避落物、生存计分、结束反馈 |
| 点亮星星 | clicker：3 条生命、30 秒 | 点击命中、误点扣命、倒计时 |

1. 从首页选择任一玩法示例，检查填入的需求和策划确认界面。
2. 配置真实模型后提交，查看八角色交付、主程分工、程序修改、审查与实际测试。
3. 试玩对应操作、得分、失败或结束、重开；三消额外检查无效交换回退和连锁。
4. 参数页按当前模式调整：三消修改步数/目标；其他模式修改生命/速度/时长。验证通过后再试玩。
5. 查看文件差异、回退与 ZIP 导出。确认失败修改不会覆盖上一可玩版本。

默认评测为五条固定需求 × 三次，覆盖全部四种模式。历史三消专项可用 `--suite match3` 复跑；结果保存在不同目录。真实模型结果需另外记录，禁止用模板或固定协议响应代替。

人工单独评价规则清晰度、操作反馈、难度和趣味性，不以编译通过代替可玩性。
